## 1. Objective & Scope
Menetapkan kontrak rilis desktop yang reproducible dan aman untuk CortexOS, mencakup:
1. Single source of truth untuk application version.
2. Propagasi version ke Wails metadata dan build artifacts.
3. Artifact naming, checksums, provenance.
4. Rollback/upgrade behavior untuk SQLite schema migrations.
5. CI release job dry-run tanpa production secrets.

## 3. Design: Single Source of Truth

### 3.1 Version File
**File:** `VERSION` (root project, committed)

```
v0.1.0
```

Format: Semantic Versioning 2.0.0 (`vMAJOR.MINOR.PATCH`), prefix `v` opsional.

### 3.2 Go Constant Generation (Build-time)
**File:** `internal/version/version.go` (generated by build script, not committed)

```go
// Code generated by build script. DO NOT EDIT.
package version

const Version = "0.1.0"
const VersionFull = "v0.1.0"
```

### 3.3 Wails Config Injection (Build-time)
During CI/build, inject `productVersion` into `wails.json` from `VERSION` file.

## 4. Artifact Naming & Provenance

### 4.1 Binary Naming Convention
```
cortexos-{version}-{os}-{arch}{.exe}
```

Examples:
- `cortexos-v0.1.0-windows-amd64.exe`
- `cortexos-v0.1.0-linux-amd64`
- `cortexos-v0.1.0-darwin-universal`

### 4.2 Checksum & Provenance Files
Per artifact, generate:
- `cortexos-{version}-{os}-{arch}.sha256` — SHA-256 checksum
- `cortexos-{version}-{os}-{arch}.provenance.json` — SLSA-style provenance (build metadata)

Provenance schema:
```json
{
  "version": "v0.1.0",
  "artifact": "cortexos-v0.1.0-linux-amd64",
  "sha256": "abc123...",
  "builtAt": "2026-10-13T05:15:00Z",
  "commit": "55ee8b1946278711b426cd770f8bcdf4b4afed14",
  "gitDescribe": "v0.1.0-0-g55ee8b1",
  "goVersion": "go1.26.3",
  "builder": "github-actions",
  "platform": "linux/amd64"
}
```

## 5. SQLite Schema Upgrade / Rollback Contract

### 5.1 Forward Compatibility (Upgrade)
- **Append-only migrations**: `ApplyMigrations()` hanya menambah tabel/kolom, tidak menghapus atau memodifikasi kolom existing.
- Schema version disimpan di tabel `{domain}_schema` (`version` integer, `name` text).
- Aplikasi versi baru **bisa** membuka DB versi lama (auto-migrate di startup).
- Aplikasi versi lama **tolak** membuka DB yang sudah dimigrasikan ke versi baru (fail-closed via `version > len(migrations)` check).

### 5.2 Rollback Procedure (Downgrade)
**NOT SUPPORTED IN-PLACE** (no down-migrations).
Rollback = **Replace entire data root with backup**.

Rollback steps:
1. **Pre-upgrade backup**: Sebelum upgrade, user/admin harus membackup seluruh `CORTEXOS_DATA_ROOT` (atau folder `state/` yang berisi 4 file SQLite: `workspace.db`, `orchestra.db`, `harness.db`, `staff.db`).
2. **Downgrade binary**: Ganti binary lama.
3. **Restore data**: Copy backup `state/*.db` ke `CORTEXOS_DATA_ROOT/state/`.
4. **Verify**: Jalankan binary lama — akan membuka DB tanpa migrasi (schema version cocok).

### 5.3 Data Root Isolation
- `CORTEXOS_DATA_ROOT` environment variable memungkinkan multiple data root per versi (e.g., `~/.cortexos/v0.1.0/`, `~/.cortexos/v0.2.0/`).
- Side-by-side installation possible by setting different `CORTEXOS_DATA_ROOT` per binary version.

## 6. CI Release Job (Dry-Run)

### 6.1 Workflow Addition
New job `release` di `.github/workflows/ci.yml`:
- Trigger: `workflow_dispatch` + tag push `v*` (manual for now).
- Runs on `ubuntu-latest`.
- Steps:
  1. Checkout
  2. Setup Go + Node + Wails
  3. Build all three platforms (matrix)
  4. Generate checksums + provenance JSON
  5. Upload as workflow artifacts (not publish to GitHub Releases)
  6. **No secrets required** — dry-run only

### 6.2 Version Bumping (Manual for now)
- Developer updates `VERSION` file manually.
- Commit: `chore: bump version to v0.1.1`
- Tag: `git tag v0.1.1 && git push origin v0.1.1`
- CI `release` job picks up tag.

## 9. Residual Risks
- **Auto-update**: Not in scope (requires code signing, update server, delta patches).
- **Schema down-migrations**: Explicitly not implemented; rollback = full data root restore from pre-upgrade backup of `state/*.db`.
- **macOS notarization**: Requires Apple Developer ID, deferred.
- **Version exposure via bridge**: `--version` entrypoint or bridge field is a planned follow-up; version is currently verifiable via `VERSION`, `internal/version`, Wails metadata, and provenance JSON.
